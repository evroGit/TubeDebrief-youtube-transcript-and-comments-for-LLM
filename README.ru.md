# Copy YouTube Comments for LLM

*[Read in English](README.md)*

Chrome extension: собирает под текущим YouTube-видео комментарии и/или транскрипт (субтитры), формирует один большой prompt и копирует его в буфер обмена — вставить в ChatGPT/Claude/Gemini/Perplexity/DeepSeek пользователь должен сам (либо это делает experimental auto-paste).

Никаких батчей, никакой интеграции с LLM API, никакого обязательного side panel — максимум простоты.

## Как это работает

1. Открываете видео на `youtube.com/watch...`.
2. Выбираете в popup, что собирать (`Что собирать`): **комментарии**, **транскрипт** или **оба** источника. По умолчанию — комментарии.
3. Нажимаете **"Copy"** — либо кнопку прямо на странице (рядом с лайком/дизлайком), либо в popup расширения.
4. Если нужен транскрипт: расширение раскрывает описание, открывает панель транскрипта YouTube и вычитывает её сегменты. Сегменты группируются в абзацы — новый абзац с таймкодом `[мм:сс]` начинается не чаще раза в `transcriptTimestampInterval` секунд, чтобы таймкоды не съели весь объём prompt. Если у видео есть главы, YouTube группирует панель по главам, и название каждой выводится заголовком `## ` над её абзацами — граница главы всегда начинает новый абзац, даже когда таймкоды отключены, а шаблоны prompt сообщают LLM, что такие строки — названия, а не произнесённый текст.
5. Если нужны комментарии: расширение переключает сортировку на "Top comments", затем скроллит страницу, подгружая комментарии (и, если включено, разворачивает replies), пока не наберёт нужное количество / объём символов. Локальный фильтр отсеивает пустые, emoji-only, ссылки-без-текста и дубликаты, оставляет комментарии не короче `minChars`/`minWords`. Прошедшие фильтр сортируются **от самых длинных**, и лимиты `maxComments`/`maxTotalChars` расходуются с начала этого порядка — то есть сортировка "Top comments" определяет, какие комментарии *прогрузятся*, а длина определяет, какие из них попадут в prompt и в каком порядке.
6. Формируется один текст: инструкция для LLM (свой шаблон на каждый режим) + транскрипт и/или пронумерованный список комментариев вида `[1] (👍 245, 87 chars) текст...`, и сохраняется (`chrome.storage.local`) как "последний скопированный текст". Когда в prompt попадают оба источника, они разделяются заголовками `=== ТРАНСКРИПТ ===` и `=== КОММЕНТАРИИ (N) ===`; при одном источнике заголовки не добавляются.
7. Текст копируется в буфер обмена.
8. Дальше **отдельно**, сколько угодно раз, нажимаете любую из кнопок **"Open ChatGPT" / "Open Claude" / "Open Gemini" / "Open Perplexity" / "Open DeepSeek"** — каждая открывает новую вкладку с этим сайтом и пытается автоматически вставить туда сохранённый текст. Сбор при этом не повторяется — можно открыть хоть все пять LLM подряд из одного Copy.
9. Если авто-вставка не сработала — вставляете вручную (Ctrl+V), текст уже в буфере обмена.

Кнопки Open остаются заблокированными (и на Copy нет галочки), пока prompt не собран именно для того видео, которое сейчас на экране. Переход на другое видео без повторного Copy снова блокирует их — поэтому клик по Open физически не может отправить в LLM prompt от другого видео.

## Что попадает в буфер обмена

В режиме **оба**, с дефолтным шаблоном и `transcriptTimestampInterval` = 30:

```
Ты анализируешь YouTube-видео: его транскрипт (субтитры) и комментарии под ним.
Видео: "Почему изменились цифры"
Ссылка: https://www.youtube.com/watch?v=abc123

Транскрипт взят из субтитров и может быть распознан автоматически: возможны
отсутствие пунктуации и ошибки в словах и именах. Учитывай это.
Комментарии отобраны локальным фильтром по длине — это не все комментарии под
видео, а 2 самых развёрнутых.

В ответе верни:
1. Краткое summary самого видео по транскрипту.
...

Ниже транскрипт и комментарии:

=== ТРАНСКРИПТ ===
[0:00] итак первое что нужно понять про это что дело никогда не было в железе
[0:31] и к 2019 году весь подход изменился поэтому цифры выглядят именно так

=== КОММЕНТАРИИ (2) ===
[1] (👍 1.2K, 75 chars) Я четыре года занимался ровно этой задачей, и все упускают дрейф калибровки.
[2] (👍 318, 81 chars) Хороший разбор, но цифра за 2019 ближе к 40%, если считать по пересмотренной базе.
```

Всё, что выше `=== ТРАНСКРИПТ ===`, — редактируемый шаблон; всё, что ниже, собирается механически. Лайки берутся у YouTube как есть, форматированной строкой (`1.2K`), без парсинга — чтобы не разбираться с локальными форматами чисел.

## Иконка статуса и badge

Иконка в панели инструментов работает и как индикатор прогресса — сбор, запущенный с самой страницы, виден даже при закрытом popup:

| Иконка | Badge | Значение |
|---|---|---|
| обычная | — | простой, либо был переход на новое видео |
| collecting | число | идёт сбор; badge показывает, сколько подходящих комментариев (или сегментов транскрипта) уже набрано |
| done | — | prompt для этого видео собран и скопирован |
| error | `!` | сбор не удался; сообщение показывает popup |

Состояние — на каждую вкладку своё. Последняя ошибка дополнительно хранится в storage, поэтому popup, открытый уже после сбоя, покажет, что именно пошло не так, а не пустую строку статуса.

## Источник данных: DOM scraping

Выбран DOM scraping страницы YouTube (не YouTube Data API), потому что:

- не нужен API key, OAuth или квоты;
- работает сразу после установки, без единой настройки;
- MVP не требует 100% полноты комментариев — только доступные без лишних действий пользователя.

Скролл прогружает ленту комментариев порциями; если включена опция **Include replies**, расширение дополнительно кликает по кнопкам "Показать ответы" перед сбором текста. Если опция выключена, ответы просто не разворачиваются и не попадают в выборку — дополнительная фильтрация не нужна.

Транскрипт читается из той же панели транскрипта, которую YouTube показывает пользователю по кнопке "Показать транскрипт". Кнопка и панель ищутся по структуре DOM, а не по тексту, — иначе понадобилась бы таблица переводов на все языки интерфейса YouTube. Транскрипт есть только у видео с субтитрами (в том числе автоматическими); если субтитров нет, панель не открывается, и режим "транскрипт" честно сообщает, что собирать нечего.

## Настройки (chrome.storage.local)

| Настройка | Где менять | Описание |
|---|---|---|
| `contentSource` | popup / options | что собирать: `comments` / `transcript` / `both`. По умолчанию `comments` — поведение до появления транскрипта |
| `minChars` | popup / options | минимальная длина комментария в символах |
| `minWords` | options | минимальное число слов |
| `maxComments` | popup / options | максимум отобранных комментариев |
| `maxTotalChars` | options | максимальный суммарный объём текста комментариев |
| `includeReplies` | popup / options | собирать ли ответы на комментарии |
| `uiLanguage` | options | язык интерфейса (popup, options, кнопки/статусы на странице YouTube) и язык prompt: `ru` / `en` / `de` |
| `transcriptTimestampInterval` | options | новый абзац транскрипта с таймкодом `[мм:сс]` начинается не чаще раза в N секунд. `0` — без таймкодов вообще (весь транскрипт одним абзацем, а если у видео есть главы — по абзацу на главу) |
| `maxTranscriptChars` | options | лимит символов на транскрипт. При превышении транскрипт обрезается по границе абзаца (а если весь транскрипт — один абзац, то по границе слова) с явной пометкой в тексте |
| `promptTemplate` | options | инструкция для LLM в режиме **комментариев** (плейсхолдеры `{{videoTitle}}`, `{{videoUrl}}`, `{{count}}`) |
| `transcriptPromptTemplate` | options | то же для режима **транскрипта**: просит summary, разбор по блокам с таймкодами и предупреждает LLM, что текст может быть распознан автоматически |
| `combinedPromptTemplate` | options | то же для режима **оба**: дополнительно просит сопоставить комментарии с содержанием видео |
| `lastPromptText` | внутреннее | последний собранный текст, используется всеми кнопками Open |
| `lastPromptVideoId` | внутреннее | id видео, для которого собран последний текст; по нему кнопки Open решают, активны они или нет |
| `lastError` | внутреннее | одна последняя ошибка (сообщение + время), показывается при открытии popup. Хранится только последняя — растущего лога нет |

Все три шаблона prompt редактируются в options, но одновременно виден только шаблон выбранного режима — остальные сохраняются как есть. При смене языка каждый шаблон автоматически переключается на дефолтный шаблон **этого** языка, только если он ещё не был кастомизирован; кастомный текст не трогается.

В режиме **оба** отсутствие транскрипта не считается ошибкой: у видео без субтитров всё равно есть комментарии, поэтому расширение собирает их, использует шаблон для комментариев и дописывает в статус "транскрипт недоступен". Ошибка — только если не собрано вообще ничего.

## Архитектура

```
manifest.json
background/service-worker.js   — открывает вкладку с LLM, дожидается её загрузки, шлёт туда текст для авто-вставки; badge с прогрессом
content/youtube.js             — инжектит кнопки Copy + Open×5, оркестрирует collect → filter → build → copy
content/autopaste.js           — experimental: вставляет текст в поле ввода ChatGPT/Claude/Gemini/Perplexity/DeepSeek
popup/popup.html, popup.js     — настройки + кнопка Copy + кнопки Open для каждого LLM
options/options.html, options.js — полный набор настроек
core/commentCollector.js       — скролл страницы, раскрытие replies, сбор сырых текстов
core/transcriptCollector.js    — открывает панель транскрипта YouTube и вычитывает её сегменты (текст + таймкод + глава)
core/filter.js                 — локальный эвристический фильтр + дедупликация + лимиты
core/promptBuilder.js          — сборка финального текста для LLM
core/i18n.js                   — словарь UI-строк и prompt-шаблонов на ru/en/de, функция t(lang, key)
core/clipboard.js              — запись в буфер обмена через offscreen-документ (fallback: navigator.clipboard / execCommand)
offscreen/offscreen.html, offscreen.js — offscreen-документ: пишет в буфер обмена без требования фокуса вкладки / user gesture (см. manifest permission "clipboardWrite")
core/targets.js                — предустановленные URL LLM-чатов
core/storage.js                — обёртка над chrome.storage.local с дефолтами + хранение последнего текста
core/openTarget.js             — общий "открыть LLM с последним текстом", используется и popup, и content script
```

Модули `core/*` подключены как обычные classic scripts (без сборки/бандлера — соответствует принципу максимальной простоты) и делят общую глобальную область видимости в контенте, куда они внедряются (content script и popup/options). Поэтому порядок загрузки в `manifest.json` значим: `core/i18n.js` должен идти до `core/storage.js` (его дефолты вызывают `getDefaultPromptTemplate`), а `core/commentCollector.js` — до `core/transcriptCollector.js` (тот переиспользует его `sleep`).

Тестов нет. Побочный плюс отсутствия бандлера: чистые модули — `filter.js`, `promptBuilder.js`, `i18n.js` — это обычные глобальные функции без единого обращения к `chrome.*`, так что их можно загрузить в Node-контекст через `vm` и прогнать напрямую (фильтрацию, группировку сегментов, обрезку, сборку prompt) без браузера. Всё, что трогает DOM или `chrome.*`, проверяется только на живой unpacked-установке.

## Permissions и зачем каждый нужен

| Permission | Зачем |
|---|---|
| `storage` | настройки, последний собранный prompt и последняя ошибка (`chrome.storage.local`) |
| `activeTab`, `scripting` | кнопка Copy в popup запускает пайплайн в активной вкладке YouTube |
| `offscreen`, `clipboardWrite` | запись в буфер обмена из offscreen-документа, у которого — в отличие от вкладки и popup — нет требования "документ должен быть в фокусе" |
| `host_permissions` на `youtube.com` | инжект кнопок Copy/Open, чтение комментариев и транскрипта |
| `host_permissions` на четыре сайта LLM | content script экспериментальной авто-вставки. Уберите сайт отсюда — кнопка Open всё равно откроет вкладку, перестанет работать только авто-вставка |

Ни `tabs`, ни удалённого кода, ни собственных сетевых запросов: всё, что расширение читает, уже есть на странице.

## Установка как unpacked extension

1. Откройте `chrome://extensions`.
2. Включите **Developer mode** (переключатель в правом верхнем углу).
3. Нажмите **Load unpacked**.
4. Выберите папку с этим расширением (там, где лежит `manifest.json`).
5. Откройте любое видео на YouTube — рядом с кнопками лайка появятся **"Copy"** и кнопки **"Open ..."**, либо откройте popup расширения через иконку в панели инструментов.

**После любого изменения `manifest.json`** (например, добавления нового домена в `host_permissions`) нужно нажать **Reload** для расширения на `chrome://extensions` — иначе новые домены/content scripts не подхватятся.

## Ограничения MVP

- DOM-селекторы YouTube могут измениться — если кнопка "Copy" перестанет собирать комментарии, вероятно, изменилась структура `ytd-comments` и селекторы в `core/commentCollector.js` нужно обновить. Панель транскрипта сейчас в процессе переезда с Polymer-элементов `ytd-*-renderer` на Lit-элементы `*-view-model`, и какое поколение достанется клиенту — зависит от раскатки, поэтому `core/transcriptCollector.js` держит оба написания в упорядоченных списках (`SEGMENT_SELECTORS`, `SEGMENT_TEXT_SELECTORS`, `SEGMENT_TIMESTAMP_SELECTORS`, `TRANSCRIPT_PANEL_SELECTORS`, `SCROLLER_SELECTORS`, `CHAPTER_TITLE_SELECTORS`), новое первым. Каждый поиск идёт по списку по одному селектору, а не склейкой через запятую: склеенный `querySelector` вернёт то совпадение, которое первое в DOM-порядке, а не то, чей селектор первый в списке, — и заложенный в порядок приоритет теряется. Чтобы добавить поколение, допишите его в начало нужного списка. Если читаемых сегментов не нашлось, `logTranscriptDiagnostics()` печатает в консоль, какое именно допущение сломалось — панель, элемент сегмента или его внутренности; начинать разбор стоит оттуда, а не с догадок.
- Сбор не гарантирует 100% всех комментариев под видео — только те, что удалось прогрузить скроллом за разумное число итераций.
- Язык дорожки субтитров не выбирается: берётся та, которую YouTube открывает в панели по умолчанию. Если у видео несколько дорожек и нужна конкретная, переключите её в панели транскрипта вручную и нажмите Copy повторно.
- Другое установленное расширение для транскриптов/суммаризации может ответить на клик по "Показать транскрипт" своей панелью — тогда родная панель YouTube не открывается, и читать нечего. Селекторы кнопки нацелены именно на обёртку кнопки YouTube, чтобы не кликать по чужому вставленному элементу, но перехват самой кнопки YouTube предотвратить нельзя. Этот случай сообщается отдельно от "нет транскрипта", вместе с обходным путём: откройте родную панель транскрипта на странице вручную и нажмите Copy снова — уже открытая панель читается как есть, без нашего клика.
- Автоматические субтитры приходят без пунктуации и заглавных букв, с ошибками в словах и именах — качество транскрипта задаёт качество summary. Шаблоны prompt для транскрипта прямо предупреждают об этом LLM, но восстановить потерянное в распознавании они не могут.
- Транскрипт длинного ролика может не поместиться в один prompt: часовое видео — это порядка 50 000 символов, и при превышении `maxTranscriptChars` текст обрезается с пометкой. Разбиения на части (map-reduce по чанкам) нет — это противоречило бы принципу "одна вставка, без API".
- Автоматическая вставка текста в чат LLM не является core-гарантией — реализована как **experimental bonus** (`content/autopaste.js`) для ChatGPT/Claude/Gemini/Perplexity/DeepSeek: после открытия вкладки и её полной загрузки расширение пытается найти поле ввода и вставить туда текст. Если селекторы сайта изменятся и вставка не сработает — это не считается ошибкой пайплайна: текст уже лежит в буфере обмена, и его можно вставить вручную (Ctrl+V).
- Язык кнопок на странице YouTube фиксируется в момент их создания (при загрузке/навигации на видео). Если сменить язык в options, пока вкладка YouTube уже открыта, кнопки на странице обновятся только после перезагрузки этой вкладки — popup обновляется сразу при каждом открытии.
- `uiLanguage` не доходит до манифеста: имя и описание расширения захардкожены (причём описание — только по-русски), поэтому в `chrome://extensions` и в Web Store они остаются неизменными независимо от выбранного языка. Для локализации нужны `_locales/` плюс `default_locale` и ссылки `__MSG_*`, чего в этом MVP нет.
